# EU AI Act Compliance Rules

Load when: `compliance.eu_ai_act: true` — AI features deployed to EU users.

**Timeline (Regulation EU 2024/1689):**
- Feb 2025: Prohibited practices (Art. 5) — ALREADY IN FORCE
- Aug 2025: GPAI obligations — ALREADY IN FORCE
- Aug 2026: High-risk system obligations — APPROACHING
- Dec 2027 / Aug 2028: Remaining Annex I/III obligations

---

## Step 1: Classify Your AI System's Risk Level

Before building any AI feature, classify it:

| Risk Tier | Description | Your Obligation |
|-----------|-------------|----------------|
| **Unacceptable** (Art. 5) | Prohibited outright | DO NOT BUILD |
| **High-Risk** (Art. 6) | Annex III categories | Full compliance: Art. 9-15, 26 |
| **Limited Risk** (Art. 50) | Interacts with users, generates content | Transparency obligations |
| **Minimal Risk** | Everything else | Voluntary codes of conduct |

### Prohibited Practices (Art. 5) — Never Build These
❌ Social scoring by public authorities
❌ Real-time biometric identification in public spaces (law enforcement)
❌ Subliminal manipulation exploiting vulnerabilities
❌ Emotion recognition in workplace or education (with exceptions)
❌ Biometric categorization by sensitive characteristics
❌ Predictive policing based on profiling

### High-Risk Categories (Annex III) — Requires Full Compliance
Your AI system is high-risk if it operates in:
- Biometric identification or categorization
- Critical infrastructure management
- Education (determining access, assessing students)
- Employment (recruiting, managing, evaluating workers)
- Essential services (credit scoring, insurance risk)
- Law enforcement
- Migration and asylum
- Administration of justice

**Most SaaS AI features are Limited Risk or Minimal Risk.**

### Limited Risk Triggers (Art. 50) — Common in SaaS
Your AI feature is Limited Risk if it:
- Interacts directly with users (chatbots, AI assistants)
- Generates synthetic text, images, audio, or video
- Performs emotion detection
- Generates or manipulates content (deepfakes)

## Limited Risk Compliance (Most Common for SaaS)

### Transparency Obligations (Art. 50)

**Chatbots / AI Assistants:**
```typescript
// REQUIRED: Inform users they are interacting with AI
// Must be CLEAR and PROMINENT — not buried in ToS

// UI: Display "AI Assistant" label visibly
// First message: "I'm an AI assistant. How can I help you?"
// Cannot deny being AI when sincerely asked

const CHATBOT_DISCLOSURE = `
  This is an AI assistant powered by [provider]. 
  It may make mistakes. For important decisions, verify with a human.
`
```

**Generated Content (Text/Images/Audio/Video):**
```typescript
// REQUIRED: Machine-readable marking for AI-generated content
// Where technically feasible: watermarking or metadata

interface AIGeneratedContent {
  content: string
  metadata: {
    aiGenerated: true          // Required flag
    model: string              // Model used
    timestamp: string          // ISO date
    provider: string           // AI provider
  }
}

// For images: embed C2PA metadata or visible watermark
// For text: include disclosure in UI near content
// "Generated by AI" label must be visible to end user
```

## High-Risk Compliance (If Applicable)

### Art. 9: Risk Management System
- Document a risk management system for the AI feature
- Identify foreseeable misuse scenarios
- Estimate residual risk after mitigation
- Update risk assessment when model or use case changes

### Art. 10: Data Governance
- Training data quality documented
- Dataset bias assessment performed
- Data collection has legal basis
- Relevant personal data is representative

### Art. 11: Technical Documentation (Annex IV)
Document before deployment:
- AI system description and intended purpose
- Human oversight measures
- Accuracy, robustness, and cybersecurity measures
- Risk management process summary

### Art. 12: Record-Keeping
```typescript
// High-risk AI systems must log:
interface AIDecisionLog {
  systemId: string
  sessionId: string
  inputHash: string       // Hash of input — never store raw PII inputs
  outputHash: string      // Hash of output
  decision: string        // What the AI recommended
  confidence: number      // Model confidence score
  humanReviewRequired: boolean
  humanReviewerId?: string
  timestamp: Date
  modelVersion: string
}
// Retention: minimum 6 months for high-risk decisions
```

### Art. 13: Transparency (High-Risk)
- Provide information to deployers about capabilities and limitations
- Document known limitations, edge cases, failure modes
- Instructions for use that allow deployers to exercise human oversight

### Art. 14: Human Oversight
- High-risk AI decisions MUST be reviewable by humans
- No fully automated decisions for high-risk categories
- Humans must be able to override, correct, or override AI
- Implement "override" or "escalate to human" pathway in UI

### Art. 26: Deployer Obligations
- Assign human oversight responsibility (named person)
- Ensure human overseers are trained and competent
- Monitor the AI system for unexpected behavior
- Suspend use if safety risk detected

## GPAI Obligations (General Purpose AI — Aug 2025)

If you are deploying a GPAI model (GPT-4, Claude, Gemini, etc.) as a service:

- Technical documentation about model training and capabilities
- Copyright policy for training data
- Summary of training data content
- Implement EU copyright law policies

**If you are a DEPLOYER (using GPAI via API):** These obligations fall on the GPAI provider (OpenAI, Anthropic, Google). Your obligation is Art. 26 (human oversight) and Art. 50 (transparency).

## EU AI Act Implementation Checklist

- [ ] AI system risk classified (Unacceptable / High / Limited / Minimal)
- [ ] No prohibited practices implemented
- [ ] Limited Risk: Transparency disclosure visible to users
- [ ] Limited Risk: AI-generated content labeled
- [ ] High-Risk: Technical documentation written (Annex IV)
- [ ] High-Risk: Risk management system documented
- [ ] High-Risk: Human oversight mechanism implemented
- [ ] High-Risk: Decision logging active (6-month retention)
- [ ] High-Risk: Human override pathway in UI
- [ ] AI system behavior monitored post-deployment
- [ ] Incident reporting process for AI failures documented

## Practical Implementation Notes

### For Typical SaaS AI Features (Limited Risk)

```typescript
// Checklist for any AI feature you ship to EU users:

// 1. Label the feature as AI in the UI
const AIFeatureBadge = () => <Badge variant="outline">AI</Badge>

// 2. Disclose in onboarding/first use
const AIDisclosure = `
  This feature uses artificial intelligence to [purpose].
  Results may not always be accurate. Review important outputs before acting on them.
`

// 3. Never deny being AI
// ❌ "I'm a human support agent"
// ✅ "I'm an AI assistant"

// 4. Mark generated content
const markAsAIGenerated = (content: string) => ({
  content,
  aiGenerated: true,
  generatedAt: new Date().toISOString(),
})

// 5. Provide easy feedback/correction mechanism
// Users must be able to flag incorrect AI outputs
```
